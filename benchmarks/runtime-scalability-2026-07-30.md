# Process-supervision runtime selection — 2026-07-30

Ronin selects a small readiness-driven supervisor built on `polling` 3.11.0.
It does not add Tokio. The selected implementation owns children and their
combined stdout/stderr streams directly, drives all captured processes from
one polling loop, and receives jobserver completions through the same poller
notification path.

## Provenance and method

The exact pre-change binary was built from
`0074fe9a17ecc3657cb795293ca891fa0a392e19`, before replacing the scoped
thread-per-child supervisor. The candidate was the dirty worktree containing
the runtime-scalability change. Both used Rust 1.92.0, release mode, and fat
LTO.

- Platform: Linux 6.12.57, x86-64
- Processor: AMD Ryzen Threadripper 2950X, 32 online logical CPUs
- Affinity and frequency: uncontrolled
- Ninja oracle: `b51a1e37c2fb89bbefa600bd155e1ce13983f09d`
- Samples: one warmup and five interleaved workload runs per tool
- Startup: median of 31 warmed `--version` launches
- Coordinator memory and thread count: `/proc/<pid>/status`, sampled every
  100 microseconds
- Workload: 1,024 independent commands at `-j256`; every command sleeps 20
  milliseconds, writes one captured byte, and creates its output

The production A/B was generated by the checked-in
`runtime-probe/benches/tool_compare.rs` harness.

| Tool | Median workload | Range | Peak threads | Peak RSS | Binary | Startup |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Ronin thread per child | 382.507 ms | 368.315–384.666 ms | 270 | 8,300 KiB | 1,410,424 B | 793,679 ns |
| Ronin evented | 356.733 ms | 342.317–361.970 ms | 1 | 4,652 KiB | 1,406,800 B | 753,040 ns |
| Pinned Ninja | 384.813 ms | 375.414–400.685 ms | 1 | 5,052 KiB | 1,464,216 B | 1,355,166 ns |

The evented implementation reduced Ronin's median by 6.7%, peak coordinator
RSS by 44.0%, and peak coordinator threads from 270 to one. Its release binary
was 3,624 bytes smaller and warmed startup was 5.1% lower. It was also 7.3%
faster than pinned Ninja on this workload while using 7.9% less coordinator
RSS.

## Isolated strategy probe

The checked-in strategy probe implements four equivalent child-supervision
loops. Each command uses a combined Unix-stream stdout/stderr channel and the
probe rejects lost output. `wakeups` means supervisor-loop wakeups: channel
completions for the threaded and Tokio cases, scan iterations for busy
polling, and successful readiness waits for evented polling.

The burst workload used 1,024 children, `-j256`, and 20 millisecond sleeps.
The idle-heavy workload used 256 children, `-j128`, and 200 millisecond
sleeps. Values are medians of five runs.

| Strategy | Burst time | Burst threads | Burst RSS | Burst wakeups | Idle time | Idle threads | Idle RSS | Idle wakeups |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Thread per child | 343.764 ms | 211 | 5,456 KiB | 1,024 | 526.787 ms | 137 | 4,120 KiB | 256 |
| Tokio current thread | 332.753 ms | 1 | 2,820 KiB | 1,024 | 447.319 ms | 1 | 2,624 KiB | 256 |
| Busy nonblocking scan | 293.618 ms | 1 | 2,312 KiB | 165 | 442.756 ms | 1 | 2,252 KiB | 1,589 |
| Evented polling | 297.739 ms | 1 | 2,236 KiB | 147 | 442.196 ms | 1 | 2,264 KiB | 246 |

Busy scanning was 1.4% faster than evented polling in the burst median, but
needed 6.5 times as many loop wakeups in the idle-heavy case. Evented polling
matched its idle-heavy throughput, used one thread, and was faster and smaller
than the Tokio alternative.

Fat-LTO probe binary sizes isolate the dependency cost:

| Enabled runtime | Binary size | Delta from threaded |
| --- | ---: | ---: |

| Evented / `polling` 3.11.0 | 560,696 B | +5,304 B (+1.0%) |
| Tokio 1.53.1 current thread | 770,056 B | +214,664 B (+38.7%) |

## Semantic verification

Performance did not decide compatibility on its own. The implementation has
dedicated tests for:

- combined stdout/stderr ordering;
- process-group interruption and partial-output cleanup;
- console-pool exclusivity;
- external jobserver wakeups and slot release;
- supervisor drop, process-group termination, and direct-child reaping;
- bounded load-average sampling;
- one sink flush per completed semantic output batch; and
- 64 simultaneously active children without a thread-per-child increase.

The full pinned Ninja suite remains the compatibility oracle and is run after
these focused tests.

## Reproduction

Build and run the isolated strategies:

```sh
probe=benchmarks/runtime-probe/Cargo.toml
CARGO_TARGET_DIR=/tmp/ronin-probe-threaded \
  cargo build --release --locked --manifest-path "$probe" \
  --bin ronin-runtime-probe
CARGO_TARGET_DIR=/tmp/ronin-probe-evented \
  cargo build --release --locked --manifest-path "$probe" \
  --bin ronin-runtime-probe --features evented-runtime
CARGO_TARGET_DIR=/tmp/ronin-probe-tokio \
  cargo build --release --locked --manifest-path "$probe" \
  --bin ronin-runtime-probe --features tokio-runtime

/tmp/ronin-probe-threaded/release/ronin-runtime-probe threaded 1024 256 20
/tmp/ronin-probe-threaded/release/ronin-runtime-probe polling 1024 256 20
/tmp/ronin-probe-evented/release/ronin-runtime-probe evented 1024 256 20
/tmp/ronin-probe-tokio/release/ronin-runtime-probe tokio 1024 256 20
```

Compare complete Ronin or Ninja binaries:

```sh
cargo build --release --manifest-path benchmarks/runtime-probe/Cargo.toml \
  --bin tool_compare
benchmarks/runtime-probe/target/release/tool_compare \
  --tool before=/path/to/pre-change/ronin \
  --tool after=target/release/ronin \
  --tool ninja=/tmp/ninja-build/ninja \
  --children 1024 --parallelism 256 --sleep-ms 20 \
  --warmups 1 --repetitions 5
```
